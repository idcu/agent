## 概述

IDCU Agent 是一个基于微内核架构的实时代理程序。微内核保持最小化，仅负责模块管理、协程调度和消息传递等核心功能。所有业务逻辑都通过可动态加载的模块实现。

### 什么是微内核架构？
微内核是一种软件架构模式，它将核心功能最小化，将大多数服务推送到用户空间模块中。

**类比：**
- **微内核** = 万能插座板
- **模块** = 各种电器（台灯、电视、空调等）

**优势：**
- 核心代码小巧易维护
- 扩展性好 - 新功能作为模块添加
- 安全性高 - 模块间隔离
- 可测试性好 - 模块可独立测试

## 微内核设计

微内核是 IDCU Agent 的核心，管理所有系统资源并协调模块执行。

### 核心组件
```c
typedef struct {
    idcu_CoroScheduler coro;           // 协程调度器
    idcu_MessageBus    msg;            // 消息总线
    idcu_Sandbox       sandbox[16];    // 沙箱环境
    uint32_t           sb_cnt;
    idcu_StackContext  global;         // 全局上下文
    volatile int       should_exit;    // 退出标志
    idcu_TrackedModule tracked_modules[16];
    uint32_t           tracked_cnt;
    idcu_DynamicLoader dynamic_loader; // 动态加载器
    idcu_HealthMonitor health_monitor; // 健康监控
} idcu_MicroKernel;
```

### 关键接口
- `idcu_kernel_init()` - 初始化微内核
- `idcu_kernel_start_modules()` - 启动所有注册的模块
- `idcu_kernel_run()` - 运行主循环
- `idcu_kernel_stop()` - 停止所有模块
- `idcu_kernel_hotplug_load()` - 热加载模块
- `idcu_kernel_hotplug_unload()` - 热卸载模块

## 模块系统

模块系统管理模块从注册到卸载的完整生命周期。

### 模块生命周期
```
注册 → 加载 → 初始化 → 启动 → 运行 → 停止 → 卸载
```

### 模块分类
模块按分类组织，用于基于优先级的加载：
- **Core**（第 0 级）** - 基础模块（日志、核心）
- **Foundation**（第 1 级）** - 基础服务
- **Monitoring/Networking/Security**（第 2 级）** - 服务模块
- **Business**（第 3 级）** - 业务功能
- **Extension**（第 4 级）** - 可选扩展

### 模块注册
模块使用 `IDCU_REGISTER_MODULE` 宏向系统注册自己。模块系统在启动时收集所有注册的模块。

## 协程调度

IDCU Agent 使用轻量级协程调度器实现高效的多任务处理。

### 调度器特性
- **轻量级** - 每个协程的开销最小
- **多优先级** - 支持不同优先级级别
- **时间片轮转** - 协程间的公平调度
- **上下文切换** - 快速的协程挂起和恢复

### 协程状态
```
就绪 → 运行 → 挂起 → 就绪
       ↓
      终止
```

### 调度流程
```
主协程
  ↓
idcu_coro_spawn() - 创建协程
  ↓
添加到调度队列
  ↓
（主循环调度）
  ↓
协程 A 运行 → 让出 → 协程 B 运行 → ...
  ↓
（时间片到期或挂起）
  ↓
切换上下文
  ↓
继续下一个协程
```

## 消息总线

消息总线实现模块之间的无缝通信，无需直接依赖。

### 消息结构
```c
typedef struct {
    uint32_t type;        // 消息类型（DATA、COMMAND、RESPONSE、EVENT）
    uint32_t sender_id;   // 发送模块 ID
    uint32_t recipient_id;// 接收模块 ID（或广播）
    uint32_t priority;    // 消息优先级
    uint32_t data_len;    // 数据长度
    uint8_t  data[];      // 消息有效载荷
} idcu_Message;
```

### 特性
- **多优先级队列** - 高优先级消息优先处理
- **零拷贝** - 高效的消息传输
- **广播** - 向所有模块发送消息
- **批量处理** - 高效处理多条消息

### 通信流程
```
模块 A（发送）
  ↓
idcu_msg_bus_send()
  ↓
消息总线（入队）
  ↓
（内核主循环分发）
  ↓
模块 B（接收）
  ↓
idcu_msg_bus_recv()
  ↓
处理消息
```

## 数据流

### 启动流程
```
main() 
  ↓
初始化日志系统（idcu_log_init）
  ↓
初始化微内核（idcu_kernel_init）
  ↓
设置信号处理器（idcu_kernel_set_signal_handler）
  ↓
加载配置文件（idcu_kernel_load_config）
  ↓
启动所有模块（idcu_kernel_start_modules）
  ├─→ 按拓扑顺序加载模块
  ├─→ 调用每个模块的 init()
  └─→ 调用每个模块的 run()
  ↓
运行主循环（idcu_kernel_run）
  ├─→ 协程调度
  ├─→ 消息分发
  ├─→ 健康检查
  └─→ ...
  ↓
（收到 Ctrl+C）
  ↓
停止所有模块（idcu_kernel_stop）
  ├─→ 调用每个模块的 stop()
  └─→ 清理资源
  ↓
关闭日志系统（idcu_log_shutdown）
  ↓
退出
```

## 设计原则

### 1. 最小化核心
保持微内核尽可能小。核心职责：
- 模块管理
- 协程调度
- 消息传递
- 基本健康监控

### 2. 模块化
所有功能都实现为模块，每个模块都有：
- 清晰的接口
- 独立的生命周期
- 可配置的启用/禁用

### 3. 松耦合
模块通过消息总线通信，无直接依赖：
- 降低耦合度
- 提高可维护性
- 便于测试和替换

### 4. 安全性
- **沙箱隔离**：模块在沙箱环境中运行
- **权限控制**：细粒度权限管理
- **资源限制**：限制模块资源使用

### 5. 可扩展性
- 易于添加新功能和模块
- 支持动态模块加载
- 清晰的扩展点

---

## 总结

IDCU Agent 的架构遵循微内核原则，通过模块化和松耦合实现了灵活、安全且可扩展的实时代理系统。
