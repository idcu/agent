# IDCU Agent 细粒度配置系统升级指南

## 概述

本文档介绍了 IDCU Agent 配置系统从 2.0 到 3.0 的升级，重点实现了更细致的配置颗粒度，使开卡过程更加友好和可控。

## 版本变更

- **旧版本**: 2.0.0 - 模块化积木式架构
- **新版本**: 3.0.0 - 细粒度配置架构

## 主要改进

### 1. 模块内部子功能细粒度控制

每个模块现在支持：
- 模块级主开关 (`enabled`)
- 子功能分组配置 (如 `channels`, `rules`, `checks`, `metrics`)
- 每个子功能的独立启用/禁用控制
- 子功能的特定参数配置

**示例配置** (`agent.cfg`):

```ini
[module.alert_module]
# 主开关
enabled = true

# 告警级别配置
alert_levels.info = true
alert_levels.warning = true
alert_levels.error = true
alert_levels.critical = true

# 通知渠道配置 - 细粒度控制
channels.email.enabled = true
channels.email.smtp_server = smtp.example.com
channels.email.smtp_port = 587

channels.webhook.enabled = true
channels.webhook.url = http://webhook.example.com/alert

channels.sms.enabled = false

# 告警规则配置
rules.cpu_high.enabled = true
rules.cpu_high.threshold = 90
rules.cpu_high.duration_ms = 60000
rules.cpu_high.channels = email,webhook
```

### 2. 细粒度权限管理

新增 `permission_manager` 模块，支持：
- 模块级权限配置
- 点号分隔的层级权限 (如 `alert.send_email`, `alert.send_webhook`)
- 权限前缀匹配 (拥有 `alert` 权限即拥有所有 `alert.*` 权限)
- 动态权限授予和撤销
- 批量权限检查 (`check_any`, `check_all`)

**示例配置**:

```ini
[permissions]
# 细粒度权限可以用点号分隔
alert_module = alert.send,alert.recv,alert.run,alert.send_email,alert.send_webhook,alert.send_sms
```

**API 使用示例**:

```c
// 检查单个权限
if (idcu_permission_check("alert_module", "alert.send_email")) {
    // 发送邮件
}

// 检查多个权限中的任意一个
const char* needed_perms[] = {"alert.send_email", "alert.send_sms"};
if (idcu_permission_check_any("alert_module", needed_perms, 2)) {
    // 至少有一个通知渠道可用
}
```

### 3. 配置管理器增强

#### 新增功能：

1. **列表解析** (`idcu_config_get_list`)
   - 解析逗号分隔的配置项为列表
   - 支持自定义分隔符
   - 自动去除空白字符

2. **列表包含检查** (`idcu_config_list_contains`)
   - 快速检查某个值是否在列表中

3. **嵌套配置读取** (`idcu_config_get_nested_*`)
   - 便捷读取层级配置
   - 自动拼接前缀和子键

4. **环境变量替换**
   - 支持 `${VAR_NAME}` 语法引用环境变量
   - 跨平台支持 (Windows/Linux)
   - 可配置开关

5. **配置验证** (`idcu_config_validate`)
   - 配置项类型验证
   - 值范围验证
   - 可配置开关

6. **配置分组/Profile** (`idcu_config_load_profile`)
   - 支持多环境配置 (development, production, etc.)
   - 快速切换配置集
   - 继承式配置覆盖

**使用示例**:

```c
// 读取列表
idcu_ConfigList targets;
idcu_config_get_list("module.heartbeat_module", "targets", ",", &targets);
for (int i = 0; i < targets.count; i++) {
    printf("Target: %s\n", targets.items[i]);
}

// 读取嵌套配置
int email_enabled = idcu_config_get_nested_bool(
    "module.alert_module", 
    "channels.email", 
    "enabled", 
    0
);

// 加载环境配置
idcu_config_load_profile("production");
```

### 4. 配置文件结构优化

#### 新增配置项：

```ini
[general]
# 配置热重载开关 (预留)
config_hot_reload = false
# 配置验证开关
config_validate = true

[resources]
# 内存限制 (字节)
memory_limit = 1073741824
# CPU 限制 (百分比)
cpu_limit = 80

[profile.development]
# 开发环境配置
log_level = debug
alert_module.channels.email.enabled = false

[profile.production]
# 生产环境配置
log_level = info
config_hot_reload = true
```

## 升级指南

### 1. 配置文件升级

旧配置文件仍然兼容，但建议按以下方式升级：

1. **添加模块级 enabled 开关**:
   ```ini
   [module.alert_module]
   enabled = true
   ```

2. **组织子功能配置**:
   - 使用点号分隔的键名组织层级
   - 按功能分组配置项

3. **添加配置分组** (可选):
   ```ini
   [profile.development]
   # 开发环境特定配置
   ```

### 2. 代码升级

#### 使用新的配置 API:

```c
// 旧方式
int enabled = idcu_config_get_bool("module.alert_module", "email_enabled", 0);

// 新方式
int enabled = idcu_config_get_nested_bool(
    "module.alert_module", 
    "channels.email", 
    "enabled", 
    0
);
```

#### 使用权限管理:

```c
// 初始化权限管理器
idcu_permission_manager_init();
idcu_permission_load_from_config("config/agent.cfg");

// 检查权限
if (idcu_permission_check("alert_module", "alert.send_email")) {
    // 执行操作
}
```

### 3. alert_module 升级示例

新的 alert_module 支持：
- 多个通知渠道独立配置
- 多个告警规则独立配置
- 告警级别过滤
- 每个规则指定通知渠道

## 开卡友好性改进

### 1. 渐进式配置

- 每个子功能都有独立的开关
- 可以逐步启用功能，降低风险
- 便于调试和问题定位

### 2. 清晰的配置结构

- 配置按功能分组，易于理解
- 注释说明每个配置项的作用
- 层级结构反映模块内部架构

### 3. 环境隔离

- 通过 profile 快速切换环境
- 敏感信息通过环境变量管理
- 不同环境的配置差异清晰可见

### 4. 权限可控

- 细粒度权限控制
- 最小权限原则
- 运行时权限检查

## 最佳实践

### 1. 配置设计原则

- **分层配置**: 模块 → 功能组 → 具体配置项
- **合理默认**: 提供安全的默认值
- **注释完整**: 每个配置项都有说明
- **向后兼容**: 保留旧配置的支持

### 2. 权限设计原则

- **最小权限**: 只授予必要的权限
- **层级清晰**: 使用点号分隔的层级结构
- **易于审计**: 权限配置清晰可读

### 3. 开卡流程建议

1. 从最小配置开始
2. 逐步启用功能
3. 验证每个步骤
4. 使用开发 profile 调试
5. 切换到生产 profile 部署

## API 参考

### 配置管理器新增 API

```c
// 列表操作
int idcu_config_get_list(const char* section, const char* key, 
                         const char* delimiter, idcu_ConfigList* out_list);
int idcu_config_list_contains(const char* section, const char* key, 
                              const char* delimiter, const char* value);

// 嵌套配置读取
int idcu_config_get_nested_bool(const char* section, const char* prefix, 
                                const char* subkey, int default_value);
int idcu_config_get_nested_int(const char* section, const char* prefix, 
                               const char* subkey, int default_value);
const char* idcu_config_get_nested_string(const char* section, const char* prefix, 
                                          const char* subkey, const char* default_value);

// 环境变量和验证
void idcu_config_enable_env_var(int enable);
void idcu_config_enable_validation(int enable);
int idcu_config_validate(void);

// 配置分组
int idcu_config_load_profile(const char* profile_name);
```

### 权限管理器 API

```c
// 初始化和加载
int idcu_permission_manager_init(void);
void idcu_permission_manager_shutdown(void);
int idcu_permission_load_from_config(const char* config_file);

// 权限检查
int idcu_permission_check(const char* module_name, const char* permission);
int idcu_permission_check_any(const char* module_name, const char** permissions, int count);
int idcu_permission_check_all(const char* module_name, const char** permissions, int count);

// 权限管理
int idcu_permission_grant(const char* module_name, const char* permission);
int idcu_permission_revoke(const char* module_name, const char* permission);

// 查询
int idcu_permission_get_module_permissions(const char* module_name, 
                                            char** out_permissions, int* out_count);
int idcu_permission_list_modules(char** out_modules, int* out_count);
```

IDCU Agent 3.0 的细粒度配置系统提供了：

✅ **模块内部子功能控制** - 每个功能可以独立开关  
✅ **细粒度权限管理** - 支持层级化权限  
✅ **列表解析** - 便捷处理多值配置  
✅ **环境变量支持** - 敏感信息安全管理  
✅ **配置分组/Profile** - 多环境快速切换  
✅ **配置验证** - 提前发现配置问题  
✅ **开卡友好** - 渐进式配置，清晰结构  

通过这些改进，开卡过程变得更加可控、安全和友好！
