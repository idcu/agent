## 版本号规范

本项目遵循 [语义化版本 2.0.0 (SemVer)](https://semver.org/lang/zh-CN/) 规范。

版本号格式：`MAJOR.MINOR.PATCH[-PRERELEASE][+BUILD]`

- **MAJOR（主版本号）**：不兼容的 API 变更
- **MINOR（次版本号）**：向下兼容的功能性新增
- **PATCH（修订号）**：向下兼容的问题修正

### 示例

- `1.0.0` - 稳定发布版本
- `1.1.0` - 新增功能，向后兼容
- `1.0.1` - Bug 修复，向后兼容
- `2.0.0` - 不兼容的 API 变更
- `1.0.0-alpha.1` - 预发布版本

## 模块与内核版本匹配规则

### 核心原则

1. **主版本号必须一致**：模块与内核的主版本号必须相同才能兼容
2. **次版本号模块 ≤ 内核**：模块的次版本号可以小于或等于内核的次版本号
3. **修订号无限制**：修订号不影响兼容性

### 匹配规则表

| 内核版本 | 模块版本 | 是否兼容 | 说明 |
|---------|---------|---------|------|
| 1.0.0 | 1.0.0 | ✅ 是 | 完全匹配 |
| 1.0.0 | 1.0.1 | ✅ 是 | 模块修订号更高，兼容 |
| 1.0.1 | 1.0.0 | ✅ 是 | 内核修订号更高，兼容 |
| 1.1.0 | 1.0.0 | ✅ 是 | 模块次版本号更低，兼容 |
| 1.0.0 | 1.1.0 | ❌ 否 | 模块次版本号更高，可能使用了内核不支持的功能 |
| 2.0.0 | 1.0.0 | ❌ 否 | 主版本号不同，不兼容 |
| 1.0.0 | 2.0.0 | ❌ 否 | 主版本号不同，不兼容 |

### 模块版本声明

每个模块必须在其 `module.json` 文件中声明其要求的最小内核版本：

```json
{
  "name": "example-module",
  "version": "1.0.0",
  "requires": {
    "idcu-agent": ">=1.0.0 <2.0.0"
  }
}
```

## 兼容性保证

### 公共 API 兼容性

- **MAJOR 版本变更**：可能破坏公共 API 兼容性
- **MINOR 版本变更**：保持公共 API 兼容性，新增 API
- **PATCH 版本变更**：保持公共 API 兼容性

### 内部 API 兼容性

内部 API（不对外公开的函数、数据结构等）在任何版本变更时都可能发生变化，不保证兼容性。

### 配置文件兼容性

- **PATCH 版本**：配置文件完全兼容
- **MINOR 版本**：配置文件向后兼容，可能新增配置项
- **MAJOR 版本**：配置文件可能不兼容，需要迁移

### 数据格式兼容性

- **持久化数据**：在 MAJOR 版本变更时可能需要迁移
- **网络协议**：MINOR 版本保持兼容，MAJOR 版本可能变更

## 升级指南

### 从 0.1.x 升级到 1.0.x

⚠️ **这是一个主版本升级，可能存在不兼容变更**

#### 升级步骤

1. **阅读 CHANGELOG**：查看 [CHANGELOG.md](../CHANGELOG.md) 了解具体变更
2. **备份配置**：备份现有配置文件
3. **测试环境验证**：先在测试环境进行升级测试
4. **逐步升级**：
   - 先升级内核到 1.0.x
   - 验证内核正常运行
   - 逐个升级模块
   - 验证每个模块的功能

#### 注意事项

- 检查模块是否有 1.0.x 版本
- 验证配置文件是否需要调整
- 测试所有关键功能

### 在 1.0.x 版本内升级

✅ **这是一个兼容升级**

#### 升级步骤

1. 查看 CHANGELOG 了解变更内容
2. 备份当前版本（可选但推荐）
3. 停止 Agent 服务
4. 替换二进制文件和模块
5. 启动 Agent 服务
6. 验证功能正常

### 模块升级最佳实践

1. **逐个升级**：一次只升级一个模块，便于排查问题
2. **先测试后生产**：在测试环境验证后再升级生产环境
3. **保留回滚方案**：升级前保留旧版本，以便快速回滚
4. **监控日志**：升级后密切关注日志输出
5. **功能验证**：验证模块的核心功能是否正常

## 常见问题

### Q: 我可以使用比内核版本新的模块吗？

A: 不建议。模块可能使用了内核不支持的新功能，可能导致运行时错误。

### Q: 旧版本的模块可以在新版本的内核上运行吗？

A: 是的，只要主版本号相同。内核保持向后兼容。

### Q: 如何检查模块与内核的兼容性？

A: 每个模块在加载时会进行版本检查，如果不兼容会拒绝加载并记录错误日志。

### Q: 主版本升级时需要做什么？

A: 请参考[升级指南](#升级指南)，通常需要：
- 阅读 CHANGELOG
- 备份数据和配置
- 在测试环境验证
- 可能需要调整配置或代码
